# 场景入口与研究链路示例

本文件是路由参考，不是固定流程。收到具体问题后按最大不确定性选方法；没有前置证据就补证、降级或跳过，不得伪造调查、实验或经营结果。示例中的名称和输出内容均为假想模板，不代表真实市场结论。

## 8 类场景

每类先给一句话启动，再列资料较充分时的用法、关键不确定性、路由、数据前提和交付。启动输入只需一句话；已有资料可直接进入适用阶段。

### 1. 验证新想法

- **一句话**：“我想为小型服务商做一个减少排班返工的工具，值得做吗？”
- **资料较充分时**：提供访谈记录、现有排班表、替代工具/流程、报价或试用记录、预计交付和获客成本；逐条核验来源，先找证据缺口。
- **关键不确定性**：问题是否频繁且重要；谁决策/付款；替代方案为何不足；可否交付并形成正向单位经济。
- **路由**：JTBD（任务不清时）→ 价值主张/商业模式 → 自下而上测算和单位经济 → 假设驱动实验；有实验分配条件才作因果推断。
- **数据前提**：用户具体经历与行为优先；意向调查不等于支付；成本未知时用明示区间，不说盈利已验证。
- **输出**：`README.md`、`report.md`、`action-plan.md`、`evidence.csv`、`research-log.md`、`artifacts/idea-validation.md`；有可审计成本数据时再附 `artifacts/economics-model.csv`。

### 2. 发现未满足需求

- **一句话**：“这个品类产品很多，还有哪些使用需求没有被满足？”
- **资料较充分时**：提供目标人群、任务/使用情境、真实访谈或工单、现有产品体验及调查原始问卷；核查样本与题项是否匹配。
- **关键不确定性**：真实任务及结果、当前替代/满意程度、未满足成果是否集中在可服务细分。
- **路由**：JTBD → 在人群/任务清晰且调查合格时 ODI → 商业性/单位经济 → 方案实验。
- **数据前提**：ODI 需真实适配调查样本和可复算口径；前提不够时只交付定性需求地图和补证计划，不给分数。
- **输出**：基础包、`artifacts/needs-map.md`；仅满足 ODI 前提时增加 `artifacts/odi-results.csv`；方案已成形时补实验方案。

### 3. 从趋势寻找机会

- **一句话**：“远程照护和人口结构变化会带来哪些服务机会？”
- **资料较充分时**：给定地区/时间范围、官方人口预测、政策原文、技术采用/成本序列、行业行为数据与已观察反例。
- **关键不确定性**：变化是否持续；如何影响具体参与者/支付者；哪些驱动可控、哪些高度不确定。
- **路由**：地平线扫描 → 驱动/情景分析 → 机会机制和受益者 → 市场测算/进入条件 → 小规模验证。
- **数据前提**：每个信号要有来源和日期；趋势相关性不等于需求/付费因果；无概率基础时不为情景标概率。
- **输出**：基础包、`artifacts/opportunity-map.md`，并在报告中列情景、信号和监测指标。

### 4. 判断技术与成本变化

- **一句话**：“某项自动化能力把处理成本压低后，能形成什么新业务？”
- **资料较充分时**：提供基准工艺、功能单位、材料/人力/能耗/良率、部署和维护记录、现场试验数据、供应与合规条件。
- **关键不确定性**：节省是否在真实系统边界内；新增集成/返工/监管成本是否抵消；价值链哪一环获得收益。
- **路由**：技术经济 → 价值链 → 进入与五力 → 单位经济/敏感性 → 交付试点；用户任务在采用机制不清时补入。
- **数据前提**：实验室性能和报价须与现场数据区分；统一功能单位和成本边界；未知参数给区间并标假设。
- **输出**：基础包、`artifacts/value-chain.md`、有可复核输入时 `artifacts/economics-model.csv`；无数据则在报告中给变量表和补测计划。

### 5. 评估跨地区或跨渠道机会

- **一句话**：“一个渠道验证过的服务，能否复制到另一个地区？”
- **资料较充分时**：提供原市场交易/留存数据、目标地区客群与竞争、官方法规、渠道报价、税费、物流/售后和支付条件。
- **关键不确定性**：需求机制是否迁移；渠道可达成本；制度/本地化门槛；既有单位经济能否保持。
- **路由**：制度与市场进入 + 本地需求/竞争 → 自下而上市场测算 → 新渠道单位经济 → 本地试点。
- **数据前提**：目标司法辖区与经营模式明确；法规引用现行主管机关原文；原市场均值不得直接外推。
- **输出**：基础包、`artifacts/entry-assessment.md`；有可比数字时附假设/敏感性分析。

### 6. 比较多个业务方向

- **一句话**：“这三个方向按现有团队资源，应该先验证哪个？”
- **资料较充分时**：提供方向描述、团队能力/时间/预算约束、现有客户证据、风险清单、可获得渠道和成本数据；可先由研究者将三个方向统一口径。
- **关键不确定性**：比较是否同一决策单位；证据强度差异是否被误当机会差异；哪个验证能以最低成本改变排序。
- **路由**：按方向分别找最大不确定性；统一使用市场/单位经济/准入维度，再用假设驱动实验排优先级。
- **数据前提**：区分已知事实和团队自报约束；任何权重/评分均写规则与依据，不能制造精确名次。
- **输出**：基础包、`artifacts/opportunity-comparison.csv`，列口径、来源、假设、证据强度与下一验证动作。

### 7. 诊断已有业务问题

- **一句话**：“用户常来试用，但付费和复购一直偏低，原因可能是什么？”
- **资料较充分时**：给去标识化事件漏斗、渠道/客群/队列、价格版本、退款/流失、客服记录、同期产品与市场变化；说明指标定义与数据缺失。
- **关键不确定性**：指标是否真实异常；获客质量、价值实现、价格、体验或交付中哪项导致变化；是否有混杂因素。
- **路由**：数据口径审计 → 竞争性原因假设 → 按最大区分力补证/实验；因果推断须有有效对照/识别策略。
- **数据前提**：真实、可追溯且同口径的历史数据；相关分群不应泄露个人信息；同期变化和选择偏差需记录。
- **输出**：基础包、`artifacts/diagnosis.md`，列原因假设、现有证据、反证、排查顺序；没有识别条件时不写“根因已确定”。

### 8. 复盘试点并决定下一步

- **一句话**：“试点跑完了，下一步该扩大、调整还是停止？”
- **资料较充分时**：提供试点目标、事前阈值、招募和分配过程、原始指标、执行偏差、成本/退款/客服负担、观察期及同期对照。
- **关键不确定性**：指标是否达到预设标准；观察到的变化是否来自干预；单位经济、交付能力和适用范围是否支持扩展。
- **路由**：审计目标/数据/实验设计 → 效果判断（满足识别条件才作因果推断）→ 单位经济/产能 → 继续、调整、停止或补证。
- **数据前提**：预设阈值、原始数据与执行日志；没有对照/可靠识别条件时只报告描述性变化，不称增量效果。
- **输出**：基础包、`artifacts/pilot-review.md`；必要时附方案修订和下一决策节点。

## 三条详细链路

### A. 需求缺口：JTBD → ODI（有前提才做）→ 商业性 → 最小验证

**示例输入**：“某类家用收纳产品评价很多，我想找未满足需求并决定是否开发改款。”

1. **选择理由与第一轮**：主要不确定性是用户在哪种情境下遇到何种结果缺口，因此先选 JTBD。公开评论可用于发现主题，但评论作者和情境不代表总体。资料较充分时输入商品退换/客服记录、访谈原文、使用情境、目标市场和品类/替代方案；先核对时间、样本、评价来源和重复样本。
2. **数据前提与补证**：提取情境、任务、替代和不满结果；把用户原话、编码和假设分栏。没有近期具体经历时，先设计中立访谈/现场观察计划，不把模型生成的“痛点”充作需求证据。
3. **ODI门禁**：只有任务、人群和单一结果题项清晰，且真实目标人群调查样本、抽样及量表可审计，才计算重要度/满意度机会排序。若样本仅为自选评论者、分母未知或题项诱导，则回退 JTBD/补充样本；无条件补证则停止量化，输出待验证。
4. **商业性与反证**：对真实优先细分自下而上测算可触达数量，比较可替代方案、生产/渠道成本和单位经济。若需求不频繁、改款成本超过可实现价格空间，或真实购买行为反驳高意向，调整价值主张或停止。
5. **实验门禁**：预先定义最小原型/报价测试、目标样本、主要行为指标与成功/停止阈值。只有真实运行后才记录观察结果；若需宣称因果提升，设计随机对照或明确合格的识别策略。

**本链路的实际交付文件**（按实际证据状态写内容，不填造数据）：

- `.bor/收纳需求缺口/README.md`：问题、状态“待验证/建议试点/调整方向/停止投入”、证据阶段和真实文件索引。
- `.bor/收纳需求缺口/report.md` 与 `action-plan.md`：JTBD发现、缺口/反证、是否满足 ODI 条件、决策和下一步阈值。
- `.bor/收纳需求缺口/evidence.csv` 与 `research-log.md`：来源/原始记录定位、范围、方法选择、门禁、回退原因和轮次。
- `.bor/收纳需求缺口/artifacts/needs-map.md`：情境—任务—期望结果—当前替代—证据—缺口表。只有 ODI 采样与口径门禁通过时才另建 `artifacts/odi-results.csv`；否则不生成假分数。

### B. 技术降本：技术经济 → 价值链 → 单位经济 → 交付验证

**示例输入**：“某项自动化技术可能让小批量检验更便宜，是否能做成按件收费的服务？”

1. **选择理由与基线**：最大不确定性是全边界单位成本变化，先用技术经济分析，而非强制从 JTBD 开始。资料较充分时输入当前工艺、功能单位、人工/设备/能耗/维护/良率/利用率、部署报价、现场节拍、供应限制和客户报价记录。没有功能单位/可靠基线时先补齐或输出变量框架。
2. **技术经济门禁**：比较同一功能单位和质量标准的基准/新方案；把实验室参数、供应商声明、现场测量分开。计算资本、变动、返工和闲置成本，呈现区间及临界利用率。若只在最佳假设下节省，结论降级为待验证；集成、维修、合规或停机成本抵消节省则回退/停止。
3. **价值链路由**：定位设备/数据/渠道/质保控制点和受益者，判断成本下降会转化为买家价格、供应者利润还是中间商收益。若客户采用障碍转为主瓶颈，补做 JTBD；不默认所有机会皆由技术性能决定。
4. **单位经济门禁**：以真实报价、每件可变成本、获客/部署/客服成本、退款返工和产能利用率建模；求贡献、盈亏临界和敏感参数。价格意向不等交易；没有真实交易时不声称利润已验证。
5. **交付验证**：设计有限范围真实交付试点，事先定质量、成本、准时率、客户行为和停止条件；若比较处理效果，确认分组/对照和污染控制。技术指标达标但客户不购买或交付不稳定，应调整服务、受众或停止。

**本链路的实际交付文件**：`.bor/自动化检验机会/README.md`、`report.md`、`action-plan.md`、`evidence.csv`、`research-log.md`；专项包括 `artifacts/value-chain.md` 和具备可追溯输入才生成的 `artifacts/economics-model.csv`。模型表列变量、单位、数值/区间、来源、事实/假设、公式；缺实测时保留缺口和测量计划，不放虚构测算结果。

### C. 试点复盘：设计/数据审计 → 效果判断 → 单位经济与产能 → 决策

**示例输入**：“一个新服务试点已经结束，请判断扩大、调整还是停止。”

1. **选择理由与入场资料**：先确认试点回答的决策问题、事前成功/停止阈值和数据是否可信；这比先解释结果更重要。资料较充分时输入预注册/方案、原始去标识化记录、招募/分配过程、执行偏差、同期事件、成本、退款、支持工时和容量数据。若用户仅一句话，照样启动：先生成最小资料清单和可独立完成的数据口径审计，不宣称已有结果。
2. **有效性门禁**：核对指标定义、分析单位、缺失/排除、观察期、重复用户、样本选择和日志一致性。找不到原始记录或关键分母时，状态为待补证；不从汇总截图反推因果。
3. **因果路由**：若随机分配、处理一致、污染可控且样本量适配，按预先指定指标估计效应与不确定性；否则说明识别条件，报告描述性结果/替代解释，不称增量效果。若结果方向与原假设冲突，回退重审执行或机制假设，不能删掉该结果。
4. **经济性与产能门禁**：把收入、退款、获客、履约、人工/客服、设备和扩容成本按单位与队列分析；检查现有样本下贡献、产能与服务质量是否可持续。指标达标但单位经济或产能不满足，调整范围/流程再测；关键安全/合规问题无法缓解则停止。
5. **决策分支**：达到事前阈值且证据与经济性/能力门禁通过，可建议有边界扩展；结果混合或外推不确定则设计下一轮；核心价值假设被否定或停止条件触发则停止并说明重启条件；证据不可得/样本不够则以待验证收敛，列最小补证，不改阈值追认成功。

**本链路的实际交付文件**：`.bor/试点复盘主题/README.md`、`report.md`、`action-plan.md`、`evidence.csv`、`research-log.md` 和 `artifacts/pilot-review.md`。复盘文件保留目标/预设阈值、数据质量、执行偏差、描述结果或因果估计（有条件才写）、单位经济/产能、限制与扩大/调整/停止/待验证理由；没有原始结果就交付审计框架与补证计划，不填模拟成实测的数字。

## 输出约定

- 所有研究运行目录以调用时当前目录下 `.bor/<研究主题>/` 为默认根；主题名不可作为绝对路径拼接或写入 Skill 安装目录。显式位置、主题清理、重名和续跑按 `{SKILL_ROOT}/references/outputs.md` 的“位置与命名”执行。
- 每条链路均沿用通用文件：`README.md`、`report.md`、`action-plan.md`、`evidence.csv`、`research-log.md`。按 `{SKILL_ROOT}/references/outputs.md` 的“场景专项映射”生成专项产物；缺证时注明未生成原因，不建空壳假装完成。
- `evidence.csv` 记录证据编号、来源/文件位置、日期、数据定位、对象范围、结论对应关系、局限与冲突；`research-log.md` 追加方法选择理由、结论、门禁、下一步及剩余额度。
- 交付完成度与机会是否成立分开标记。研究计划、市场估计、真实调查、实验结果必须彼此区分。
